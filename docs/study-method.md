# Método de estudio

[Inicio](../README.md) · [Roadmap](../ROADMAP.md)

Para cada lección: lee el problema, dibuja el modelo y predice la salida del ejemplo antes de ejecutarlo. Compara la predicción con la salida real y explica cualquier diferencia. Cambia un dato del ejemplo y predice otra vez; no copies ese programa para resolver el ejercicio.

Resuelve el guiado usando primero el enunciado; abre pistas solo después de escribir una hipótesis. El desafío es independiente y no tiene receta. Las respuestas en `self-assessment` explican conceptos, no implementaciones. Responde sin mirarlas, luego contrasta tu razonamiento y vuelve al apartado correspondiente si no puedes explicar el porqué.

Avanza cuando puedas explicar el mecanismo, satisfacer la aceptación del ejercicio y justificar al menos un tradeoff. Puedes avanzar sin un tutor; anota qué no comprendiste para revisarlo. Un test verde no demuestra que entiendas aliasing, coordinación o errores. Tampoco un fallo aislado demuestra una dificultad permanente.

En PROGRESS separa «leído», «ejecutado», «resuelto» y «explicado». Anota evidencia concreta (comando, resultado, hipótesis). No marques ejercicios por el simple hecho de abrirlos. No hay fechas límite.

Para solicitar revisión, comparte tu implementación, el requisito, comando, salida y explicación. El agente no debe reemplazar tu trabajo. Para bugs intencionales, investiga causa y reparación por ti mismo; registra la diferencia entre la versión defectuosa y tu alternativa.
