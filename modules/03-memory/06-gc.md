## Motivación

La memoria automática reduce errores manuales, pero el programa todavía controla cuánto retiene y cuánto asigna.

## Explicación conceptual

El garbage collector recupera memoria de objetos que ya no son alcanzables desde raíces relevantes del programa. No libera un objeto solo porque saliste de un bloque ni porque llamaste a Close: recursos externos y memoria tienen ciclos de vida diferentes.

El GC de Go realiza trabajo concurrente con la aplicación y tiene pausas y coordinación. Su implementación evoluciona; Go 1.26 habilita Green Tea por defecto. La lección no depende de detalles de sus regiones o instrucciones. El contrato importante es validez de objetos alcanzables, no un instante preciso de liberación.

Más asignación y más memoria viva pueden aumentar coste. GOGC controla una relación de crecimiento objetivo del heap; GOMEMLIMIT orienta un límite de memoria administrada por runtime, no garantiza limitar todo RSS del proceso. Ajustar esos valores intercambia frecuencia de colección, CPU y memoria, y exige medir carga real.

GC no cierra sockets, archivos o transacciones a tiempo. Finalizers no son una política fiable de liberación determinista. Usa Close y context donde corresponda. Go usa GC para simplificar seguridad y composición frente a liberación manual; a cambio requiere presupuesto de runtime y atención a retención.

## Sintaxis y ejemplos

[Programa completo](examples/06-gc/main.go):

```go
package main

import (
	"fmt"
	"runtime"
)

func main() {
	var stats runtime.MemStats
	runtime.ReadMemStats(&stats)
	fmt.Printf("heap=%d gc-cycles=%d\n", stats.HeapAlloc, stats.NumGC)
}
```

Desde la raíz:

```sh
go run ./modules/03-memory/examples/06-gc
go build -o /tmp/go-from-zero-example ./modules/03-memory/examples/06-gc
```

**Resultado e interpretación:** Las cifras varían. La salida permite observar el proceso, no deducir una política universal de GC.

Antes de ejecutarlo, anota tu predicción. Después señala qué instrucción explica cada resultado y qué propiedad no demuestra esta ejecución.

## Comparación con otros lenguajes

C libera explícitamente; Java también tiene GC con otros collectors y configuraciones. Python combina mecanismos que no equivalen al de Go.

## Errores comunes

GC=Close; GOMEMLIMIT=RSS duro; forzar GC en cada request; retener caches sin límites.

Si observas un fallo, conserva el mensaje exacto y una hipótesis. Compilar y ejecutar son verificaciones diferentes; no arregles por ensayo ciego.
